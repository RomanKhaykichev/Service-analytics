## Почему метрики могли обрезаться до 13.02

1. **Формат с временем:** в ячейках хранится `DD.MM.YYYY HH:MM`. Старый код вызывал `to_timestamp(..., 'DD.MM.YYYY')` на всей строке; в PostgreSQL это могло давать ошибку/NULL для строк с хвостом времени, и такие строки отбрасывались в `populate_facts` (`WHERE date_created IS NOT NULL`).

2. **Исправление в коде:**
   - В SQL для формата `DD.MM.YYYY` (и с временем) берётся только дата:  
     `substring(trim(created_at_raw) from '^[0-9]{2}\.[0-9]{2}\.[0-9]{4}')` → затем `to_timestamp(..., 'DD.MM.YYYY')`.
   - При чтении Excel в Python даты нормализуются в `YYYY-MM-DD` (в т.ч. из `DD.MM.YYYY HH:MM` и других вариантов отображения).
