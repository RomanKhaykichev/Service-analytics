# Поддержка загрузки файлов на узбекском (UZ)

## Идея

Сервис принимает те же 4 типа файлов (seller/storage, sells/sales, expenses, left_out_old) в двух вариантах:
- **RU** — заголовки на русском (как раньше);
- **UZ** — заголовки на узбекском.

После приведения заголовков к **каноническому виду (RU)** используется один и тот же pipeline импорта и расчётов. Логика метрик не меняется.

## Где лежит маппинг

- **Модуль маппинга:** `apps/api/app/utils/column_mappings.py`
  - Канонические имена колонок (RU) по типам файлов: `CANONICAL_*`, `CANONICAL_BY_FILE_TYPE`.
  - Словари UZ → RU: `UZ_TO_RU_SALES`, `UZ_TO_RU_EXPENSES`, `UZ_TO_RU_LEFTOUT`, `UZ_TO_RU_STORAGE`, `UZ_TO_RU_LEFTOUT_OLD`, `UZ_TO_RU_BY_FILE_TYPE`.
  - Функции: `normalize_header`, `map_headers_to_canonical`, `detect_language`.
  - Ошибки: `DuplicateCanonicalError`, `MissingRequiredColumnsError`.

- **Использование в импорте:** `apps/api/app/routes/imports.py`
  - После чтения Excel и нормализации заголовков вызывается `map_headers_to_canonical(file_type, list(df.columns), required_canonical)`.
  - Колонки переименовываются в канонические (RU), далее без изменений: `validate_required`, `to_staging`, `populate_facts`.

## Авто-определение языка

Язык (RU/UZ) определяется по заголовкам автоматически; в UI ничего выбирать не нужно. Если больше заголовков совпадают с UZ-маппингом — считается UZ, иначе RU.

## Валидация и ошибки

- После маппинга проверяются обязательные канонические колонки (как для RU).
- Если чего-то не хватает — возвращается ошибка с:
  - списком отсутствующих канонических колонок;
  - подсказкой, как они могут называться в UZ (из маппинга).
- Если в одном файле одновременно есть и RU-, и UZ-варианты одной и той же колонки (два заголовка маппятся в один канонический) — возвращается конфликт с понятным текстом.

## Как подставить реальные UZ-заголовки

Текущие UZ-заголовки в коде — типовые (латиница). Если в ваших выгрузках UZUM заголовки другие:

1. Положите RU-файлы в папку, например `samples/ru`, UZ — в `samples/uz` (или укажите пути в скрипте).
2. Запустите скрипт сравнения (из корня репозитория, при необходимости добавьте `apps/api` в `PYTHONPATH`):

   ```bash
   python tools/compare_ru_uz_import.py --ru-dir "C:\path\to\Выгрузки_ RU" --uz-dir "C:\path\to\Выгрузки_Uzb"
   ```

3. По выводу скрипта (пары UZ → RU) добавьте или измените записи в `UZ_TO_RU_*` в `apps/api/app/utils/column_mappings.py`. Ключи в словаре — нормализованные (trim, lowercase) UZ-заголовки.

Имена файлов в папках могут быть, например: `seller.xlsx`, `sells.xlsx`, `expenses.xlsx`, `left_out_old.xlsx` (или `storage.xlsx`, `sales.xlsx` и т.п. — см. `FILE_CONFIG` в скрипте).

## Как проверить вручную в UI

1. **Загрузка RU (как раньше)**  
   Загрузите 4 файла на русском (seller, sells, expenses, left_out_old). Импорт и метрики должны работать как до изменений.

2. **Загрузка UZ**  
   Очистите данные (или используйте тестового пользователя), загрузите те же 4 типа файлов на узбекском (из папки Выгрузки_Uzb).  
   Ожидание: импорт проходит успешно, ключевые метрики совпадают с импортом RU-набора на тех же данных.

3. **Ошибки**  
   - Попробуйте загрузить файл с недостающими обязательными колонками — должен вернуться понятный ответ с перечислением отсутствующих колонок и подсказкой по UZ-названиям.  
   - Если в файле окажутся и RU-, и UZ-варианты одной колонки — должна вернуться ошибка о конфликте.

## Габаритная группа (рус–узб): заголовки, значения, цвета

- **Заголовок колонки** в выгрузках: RU — «Габаритная группа», UZ — «Gabarit guruhi», «O'lchov guruhi», «O'lchamlar guruhi» (маппинг в `column_mappings.py` → каноническое «Габаритная группа»).
- **Значения в ячейках** (отчёт по хранению / storage): при импорте UZ-значения приводятся к тем же, что в RU, в `apps/api/app/utils/value_mappings.py`:
  - RU: **СГТ**, **МГТ**, **БГТ**
  - UZ → RU: Kichik / Kichik gabaritli / Kichik o'lchamli → СГТ; O'rta / Orta / O'rta gabaritli → МГТ; Katta / Katta gabaritli → БГТ (и по подстрокам).
- **Цвета в UI** (таблица товаров и карточка товара): сопоставление по файлам seller-storage (выгрузки Uzum). **KGT (узб) = МГТ (рус)** = оранжевый; **OʻGT (узб) = СГТ (рус)** = зелёный (в файле используется O с апострофом U+02BB); **BGT = БГТ** = красный. Полные названия: Kichik→зелёный, O'rta→оранжевый, Katta→красный. Логика в `getSizeGroupColorClass()` в `apps/web/src/lib/utils.ts`.

- **Рекомендации по отгрузке** (left-out-report_old): сопоставление рус–узб для колонок «Продаж в день», «Запланировано к отгрузке», «На складе». В `column_mappings.py` (UZ_TO_RU_LEFTOUT_OLD): **Среднесуточные продажи** ← Sutkalik o'rtacha sotuvlar, 15 kun ichida FBO o'rtacha kunlik sotuvlari, dona; **К отправке** ← Yuborishga, Yuborishga mavjud; **Общий остаток** ← Umumiy qoldiq. В `charts.py` при чтении jsonb для эндпоинта рекомендаций по отгрузке используются ключи RU и UZ (`_get_data_ru_uz`), чтобы «Продаж в день», «Запланировано к отгрузке» и рекомендуемое кол-во (формула на фронте: от `sales_per_day` и `turnover`) работали и для узбекских выгрузок.
- **Сравнение значений в ваших файлах:** из корня репозитория (с путями к папкам RU и UZ):
  ```bash
  python tools/compare_ru_uz_import.py --ru-dir "C:\path\to\Выгрузки_ RU" --uz-dir "C:\path\to\Выгрузки_Uzb" --size-group-values
  ```
  Скрипт выведет уникальные значения колонки «Габаритная группа» в RU и UZ по отчёту storage; по ним можно сверить соответствие и при необходимости добавить варианты в `value_mappings.py` (SIZE_GROUP_UZ_TO_RU и подстроки в `_map_size_group`).

Расширение на другой язык: добавить в `column_mappings.py` новый словарь (например `EN_TO_RU_*` или `LANG_TO_RU_*`) и в `map_headers_to_canonical` по очереди проверять все языковые словари (и/или вынести конфиг в JSON/YAML при необходимости).
